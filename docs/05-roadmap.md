# 迭代计划与验收

状态：提案。仓库当前仅完成设计整理，以下实现阶段均未开始。

## 阶段总览

| 阶段 | 目标 | 交付物 | 进入下一阶段的门槛 |
| --- | --- | --- | --- |
| P0 | 链路原型与连接验证 | 首次/再次使用原型、技术验证、后端选型记录 | 用户能走通交接；真机闭环可重复，失败可恢复 |
| P1 | 通用手机工具 | 协议与观察/操作闭环 | 无需通用 shell 完成基础操作 |
| P2 | 可用 Alpha | 控制体验、任务结果、会话独占 | 暂停/接管有效，跨 App 生命周期正确 |
| P3 | 端到端体验 Beta | 通用任务验证、可用性报告、回归样例 | 少重述、少折返、能接续，结果有据 |
| P4 | 扩展 | 易启用后端与跨 App 任务 | 能力、授权和分发要求均明确 |

工期在 P0 后估算。实现任务可以在依赖满足时并行规划，但发布必须通过阶段门槛。

## P0：链路原型与连接底座

- [ ] 用低保真原型走通表达目标、首次准备、再次启动、接管、恢复和收尾。
- [ ] 找出设置页往返、重复输入、进度不明和接管入口不可达的阻碍。
- [ ] 验证匹配 ABI 的 ADB 与原生协议客户端路线。
- [ ] 验证 Android 11+ 的配对、手动连接与自动发现。
- [ ] 设计密钥私有存储、解除配对、端口变化和设备去重。
- [ ] 验证切换到其他 App 后运行时和控制桥仍可接收请求。
- [ ] 验证断连、进程被结束、锁屏和通知控制。
- [ ] 形成选型记录与初版设备支持表。

体验验收：使用独立构造的目标和合成数据做引导测试，记录首次设置的放弃点；返回宿主时保留目标，配对失败不重置完整向导。此阶段不需要实现业务自动化。

验收：至少一台 arm64 真机和一个 Android 模拟器；连接/断连和 App 切换各做 10 次，记录每次条件与结果。模拟器通过不替代真机结论。公开结果必须匿名化。

## P1：通用工具

- [ ] 实现能力查询、启动、快照、截图、点击、滑动、输入、返回。
- [ ] 实现宿主身份绑定与请求去重。
- [ ] 实现观察引用与截图几何校验。
- [ ] 实现取消、超时和结果未知状态。
- [ ] 验证中文输入路线并准确声明能力。
- [ ] 以协议测试覆盖重复请求、取消竞争、旧引用与错误输出。

验收：Agent 不依赖任意 shell 即可完成一个完整的读取任务和一个测试环境中的提交任务。窗口旋转或改变后，旧观察不能被继续执行。

## P2：可用 Alpha

- [ ] 配对向导与聊天任务卡。
- [ ] 用户可见的执行通知和暂停/停止入口。
- [ ] 会话独占、接管与重新观察后恢复。
- [ ] 设备锁定、宿主切换与后台回收的明确状态。
- [ ] 私有临时素材生命周期和数据路径说明。
- [ ] 结果卡区分派发状态、观察状态和业务事实。
- [ ] 明确触达分级：持续运行状态、需要用户处理、控制失效和任务结束分别呈现。
- [ ] 浮窗与通知共享任务状态、等待原因和下一步，旧事件不能覆盖新状态。
- [ ] 触达检查覆盖授权、系统接收、展示确认与用户回应；通道失效时停止新的修改动作。
- [ ] 真机验证通知权限受限、浮窗不可用、宿主回收和厂商省电策略下的降级路径。
- [ ] 区分暂停请求和暂停生效，人工敏感步骤期间停止观察。
- [ ] 连接或页面恢复后保留目标和已确认进度。

验收：第二会话不能抢占设备；用户接管后不再发出新修改动作；恢复不会自动重放提交。目标 App 在前台时任务可继续，返回宿主后状态一致。

## P3：端到端体验打磨

以通用读取、编辑、页面操作和多步骤导航作为验证载体，采用独立构造的任务与合成数据。评价的是完整旅程，不是特定 App 的功能适配数量。

- [ ] 明确目标直接开始，影响动作的歧义一次问清。
- [ ] 已配置用户不重复走配对向导或输入技术参数。
- [ ] 用户分得清正在执行、加载、重连和等待自己处理。
- [ ] 接管入口在跨 App 期间可达，反馈与实际控制状态一致。
- [ ] 登录或手工修正后能够从可验证进度继续，不重述完整目标。
- [ ] 用户途中改目标时停止冲突动作，保留已完成事实。
- [ ] 结果区分完成、部分完成、外部处理中和无法确认。
- [ ] 任务结束后交还控制，结果入口可达，不突然抢回界面。

验收：在首次使用、再次使用、慢任务、中途打断、恢复和收尾六条旅程中，记录完成率、切换次数、重复输入、误解、放弃点和恢复耗时。让测试者复述当前控制者、等待原因与完成范围，不能只测按钮能否点击。关键旅程中无法拿回控制、误判完成或重复提交均阻断发布。

## P4：扩展

- [ ] 评估 AccessibilityService 与必要的屏幕采集后端。
- [ ] 检查各系统版本能力与目标分发渠道的现行要求。
- [ ] 统一后端能力声明，验证中文输入和手势差异。
- [ ] 扩展跨 App 的查询、比较与整理任务。
- [ ] 单独论证独立客户端、远程控制和定时执行的范围。

验收：新增后端不绕过接管语义；切换后重新观察。无人值守能力需要独立设备可用性和恢复证据，不能由手动任务成功推导。

## 验证矩阵

| 维度 | 代表场景 | 证据 |
| --- | --- | --- |
| 连接 | 配对过期、端口变化、自动发现失败 | 状态、重连结果、匿名诊断 |
| 生命周期 | 切 App、宿主后台、锁屏、进程结束 | 请求接纳/拒绝和通知状态 |
| 几何 | 旋转、键盘、缩放、分屏、弹窗 | 引用失效与实际观察 |
| 并发 | 两个会话、取消与派发竞争 | 唯一拥有者、单次派发 |
| 任务结果 | 完成、部分完成、仍在处理、结果不明 | 页面证据与完成范围一致 |
| 用户旅程 | 首次设置、慢任务、手工介入、恢复、收尾 | 重述次数、切换次数、控制反馈与用户理解 |
| 触达 | 普通运行、需要处理、控制失效、任务结束 | 通道授权、接收/展示证据、控制入口与后续动作一致 |
| 数据 | 临时素材清理、日志脱敏 | 私有路径生命周期、无明文凭据 |

## 发布阻断项

- 无证据声称业务成功或整个任务已完成。
- 用户暂停/接管后仍派发新修改动作。
- 浮窗和通知都不可用或无法确认控制入口可达时，仍继续修改操作。
- 把通知发送成功、系统接收或通道展示说成用户已经知悉。
- 超时或重连后重复提交未知结果的动作。
- 旧截图/旧节点被错误用于新窗口。
- 凭据或私人页面数据进入公开仓库、演示或诊断日志。
