# 架构设计

状态：提案。模块名用于说明职责，并非现有目录或已发布组件。

## 1. 系统边界

PalmRelay 的核心是 Android 设备控制能力与 Agent 工具协议，而不是另造一套大模型或聊天后端。

首个集成目标是 AndChamber 的本地运行模式。独立仓库承载设计，后续可将 Android 控制核心作为宿主内组件实现；是否打包独立客户端，需要在技术验证后决定。

```text
用户任务 / 聊天 UI
        │
        ▼
Agent 宿主（首选 AndChamber / OpenCode 集成）
        │  palmrelay_phone 工具调用
        ▼
宿主适配器 ── 仅本机的认证传输 ── Android 控制桥
                                      │
                              会话租约 / 取消 / 去重
                                      │
                              PhoneController
                              /             \
                       Observation       ActionDispatcher
                              \             /
                               DeviceDriver
                               /          \
                        ADB 后端       后续能力后端
                               \          /
                                 Android App

Android 任务状态 ──► 聊天任务卡 / 系统通知 / 悬浮控制条
```

## 2. 模块职责

| 建议模块 | 职责 |
| --- | --- |
| `phone/core` | 设备能力、观察模型、动作模型、执行租约与状态 |
| `phone/driver/adb` | 配对、发现、连接、截图、节点读取、动作派发 |
| `phone/tool` | 请求验证、认证、请求去重、截止时间与取消 |
| `phone/session` | 单会话独占、用户接管、锁屏和任务生命周期 |
| `phone/task` | 目标摘要、任务阶段、等待原因、已确认进度、未决动作与有序事件 |
| `phone/evidence` | 结果证据引用、私有暂存与清理 |
| `ui/phone` | 配对向导、任务进度、暂停/接管/恢复 |
| `phone/attention` | 统一状态投影、提醒分级、权限与触达检查、旧事件丢弃 |
| `integration/agent` | Agent 工具 schema、宿主身份绑定与结果回传 |

## 3. 借鉴已有能力

AndChamber 的浏览器工具设计已有可参考的模式：

- App 注入宿主工具插件。
- 私有 endpoint 描述文件与每次启动轮换的认证凭据。
- loopback 传输、请求身份、去重、取消与超时。
- 观察引用与页面身份校验。
- 将“动作派发”与“业务完成”分开。

手机控制需要独立驱动、协议语义和生命周期。实现时先明确兼容边界，再决定哪些代码可以抽取复用，并核对来源许可。

尤其不能照搬浏览器“宿主 Activity 进入后台即撤销”的逻辑：打开目标 App 正是手机任务的正常过程。

## 4. ADB 后端选型

本次探索使用的外部工具链存在架构转译和子进程生命周期问题，不能直接包装为产品底座。

P0 对比两条路线：

| 路线 | 优势 | 必须验证的问题 |
| --- | --- | --- |
| 匹配 ABI 的 ADB 子进程 | 行为接近现有 ADB 工具，原型迁移直接 | Android 可执行文件加载限制、编译与分发、后台存活、进程收尾、许可证 |
| Android 原生 ADB 协议客户端 | 连接与生命周期更容易由宿主管理 | TLS 配对兼容、密钥管理、协议完整度、维护成本 |

门槛：实际手机上完成首次配对、连接、观察、操作和恢复；不能仅凭库的 README 或模拟器结果定案。

节点读取与中文输入能力也要单独验证。ADB shell 可调用的输入能力不等同于无障碍节点的 `setText`；不能宣称所有后端都具备相同能力。

## 5. 连接与设备身份

- 连接地址会变化，不能把端口当作设备身份。
- 结合配对身份与连接信息，将自动发现和手动直连归并为一部设备。
- mDNS 发现失败时允许用户输入系统显示的连接地址和端口。
- 自动重连只恢复传输，不自动恢复控制权或重放之前动作。
- 同一设备只允许一个有效执行租约；新会话不能挤掉已有会话。
- 解除配对时清理本地凭据，并指导用户删除系统端授权；不能把本地删除描述为设备端已撤销。

## 6. 跨 App 生命周期

将以下状态分开：

1. 宿主 UI 是否可见。
2. 运行时和控制桥是否存活。
3. 设备是否连接、亮屏、解锁。
4. 会话是否持有有效租约。
5. 当前动作是否已经派发。

目标 App 在前台并不意味着撤销租约；锁屏、用户接管、任务停止或运行时身份改变则停止接纳新动作。

采用符合当前 Android 限制的用户可见执行生命周期。前台服务类型、后台启动限制、通知动作和厂商省电策略属于 P0 验证项，不能把“开一个前台服务”当作长期保活保证。

## 7. 观察与执行闭环

1. 检查连接、会话所有权和能力。
2. 获取快照：包名、窗口、方向、可见节点、时间戳。
3. 按需要获取截图，并绑定同一观察版本。
4. Agent 选择动作，控制桥检查最新窗口身份、引用和坐标几何。
5. 派发一次动作，记录是否已经到达后端。
6. 在有界时间内观察变化，返回派发状态和观察结果。
7. Agent 根据业务页面判断任务结果；必要时打开记录核对。

节点树和截图并非天然原子获取。若前台窗口或几何在采集过程中改变，丢弃本次组合或明确标识不一致，重新观察后再允许操作。

## 8. 截图与输入

- 节点操作优先，减少分辨率、字体和布局变化导致的偏移。
- 坐标兜底必须绑定最新截图与旋转状态；弹窗、键盘、分屏、显示缩放都可能使坐标失效。
- 截图不能读取受系统保护的内容时，返回不支持或需用户处理。
- 输入能力按后端声明：基础文本、Unicode、替换/追加、提交键分别建模。
- 如需输入法桥，由用户显式启用，确认其输入范围和恢复方式。
- 对看不到的页面，不根据旧图猜测点击。

## 9. 传输与证据

首版只支持本机认证通道，不把控制端口暴露到局域网或公网。认证凭据置于私有存储，随启动轮换，并与会话执行租约分离。

每个请求有唯一标识，取消和超时信息随请求记录。接口不提供通用 shell，动作范围由显式 schema 定义。

业务证据引用只包含必要页面摘录、观察时间与状态；截图不默认进入长期历史。所有证据作为不可信页面数据，不可提升为新的用户指令。

## 10. 扩展后端

后续评估 AccessibilityService 的节点、手势、输入和截图能力，以及必要时的 MediaProjection 路线。系统版本、用户授权、分发政策与后台限制都影响可用能力。

统一工具契约通过能力查询适配差异；后端切换必须撤销旧观察和未完成的动作假设，不为绕过用户接管而切换后端。

## 11. 用户旅程对架构的要求

任务目标、设备连接、执行租约和单次动作是不同生命周期。连接中断或跳到设置页不能顺带丢弃用户目标；任务完成也不能等同于“最后一个工具返回成功”。

- `phone/task` 维护唯一任务状态源，聊天卡、通知与可选控制条订阅同一份状态。
- 保存最小目标摘要、已确认进度与未决动作标识；敏感输入、配对码和屏幕历史不随草稿持久化。
- 控制事件携带任务身份、运行时身份和有序序号，丢弃过期事件，避免界面恢复后显示旧的执行状态。
- `phone/attention` 将同一任务状态投影到聊天卡、系统通知和浮窗；分别记录通道授权、系统接收、展示确认与用户回应，不能用“已发送”代替“已知悉”。
- 执行前检查触达通道，至少保留一条经验证的用户主动启用的控制入口；执行中失去全部可信入口时停止接纳新的修改动作，并在能展示的通道说明恢复方式。
- 系统通知、前台服务、浮窗和后台启动都受系统权限与厂商策略限制，必须在真机上验证接收与展示条件，不能只凭 API 调用返回判断触达成功。
- 用户点击暂停先得到即时 UI 回应，执行层确认后再显示“已暂停”；控制通道不等待模型生成回复。
- 登录等人工步骤期间关闭观察，用户继续后才恢复页面采集。
- 中断恢复先对照当前页面与已确认事实，再决定下一步；无法恢复的上下文明确告知用户。
- 观察、模型决策、页面加载和重连分别记时，为等待原因和慢任务反馈提供实际数据。

具体界面行为以[端到端用户体验](04-experience.md)为准。体验测试应早于完整功能实现，避免先固定底层协议再发现它无法支持可靠的交接。
