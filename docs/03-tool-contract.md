# 工具协议草案

状态：设计提案 v0，未实现，不保证向后兼容。

## 1. 工具名称与原则

建议名称：`palmrelay_phone`。

宿主适配器可以映射已有命名，但应保持协议版本与动作语义一致。每次调用只执行一个动作；观察可以组合返回文本和图像。

## 2. 动作

| action | 输入重点 | 输出重点 |
| --- | --- | --- |
| `status` | 目标设备（首版默认本机） | 连接、能力、租约状态；不得泄露密钥 |
| `launch` | 已识别的 `packageName` | 启动状态、实际前台 App、新观察要求 |
| `snapshot` | 可选的观察范围 | 节点 refs、窗口身份、方向、时间、能力 |
| `capture` | 可选的当前观察 ID | 图像、屏幕几何、绑定的观察 ID |
| `tap` | ref，或观察 ID 与坐标 | 派发状态与后续观察 |
| `swipe` | 当前观察 ID、方向/受限轨迹 | 派发状态、是否发生可见变化 |
| `input` | 可编辑 ref、文本、替换/追加模式 | 输入派发状态；不默认提交 |
| `back` | 当前观察 ID | 返回派发状态、实际前台窗口 |

应用发现由用户选 App、任务入口绑定或后端最小化解析提供；模糊名称无法唯一匹配时询问用户，不凭猜测启动其他 App。

暂停、接管和恢复由可信宿主 UI 管理。Agent 不能通过工具自行批准被撤销的租约。

## 3. 请求信封

以下为合成示例，身份字段由可信宿主填充，不允许模型自选另一个会话身份。

```json
{
  "protocolVersion": 0,
  "requestId": "req-example-01",
  "sessionId": "session-example",
  "runtimeEpoch": "runtime-example",
  "leaseId": "lease-example",
  "timeoutMs": 15000,
  "action": "tap",
  "args": {
    "observationId": "obs-example-04",
    "ref": "node-12"
  }
}
```

- 传输认证独立于 JSON 内容，不能仅因知道 `leaseId` 就获授权。
- 请求身份按运行时、会话、请求 ID 共同限定。
- `timeoutMs` 受服务端上限约束，不允许无限期持有执行槽。
- `status` 可以在没有租约时返回最小能力信息；截图和界面读取需要有效的任务观察权限。
- `tap` 的 ref 与坐标互斥；所有修改动作都要求合适的新鲜观察。

## 4. 观察模型

```json
{
  "observationId": "obs-example-04",
  "observedAt": "2026-01-01T12:00:00Z",
  "packageName": "com.example.workspace",
  "windowEpoch": "window-example-02",
  "rotation": 0,
  "display": { "width": 1080, "height": 2400 },
  "nodes": [
    {
      "ref": "node-12",
      "role": "button",
      "text": "保存",
      "enabled": true,
      "bounds": [40, 2100, 1040, 2240]
    }
  ]
}
```

示例时间与包名均为虚构。

refs 仅在当前观察与窗口上下文中有效，不作为跨页永久 ID。发生旋转、前台包变化、窗口替换、用户接管或后端重连时撤销旧观察。

时间新鲜度不足以证明页面未变；执行前还要检查窗口身份与目标节点。无法可靠确认时要求重新观察。

## 5. 响应模型

```json
{
  "protocolVersion": 0,
  "requestId": "req-example-01",
  "ok": true,
  "action": "tap",
  "dispatch": "sent",
  "outcome": "observed",
  "observationId": "obs-example-05",
  "businessResult": {
    "status": "not_determined",
    "evidenceRefs": []
  },
  "requiresSnapshot": true
}
```

`ok` 表示工具请求被正常处理，不表示用户目标已经完成。

| 字段 | 取值与含义 |
| --- | --- |
| `dispatch` | `not_sent` 未派发；`sent` 已派发；`unknown` 无法确定是否派发 |
| `outcome` | `not_attempted`；`observed` 已观察；`unknown` 无法确认效果 |
| `businessResult.status` | `not_determined`、`pending`、`confirmed`、`rejected` |

通用驱动不凭点击回执填写 `confirmed`。业务确认须提供可核对证据；`confirmed` 只证明一个明确事实，不自动等同于整个任务完成。宿主结果层还应包含事实类型、摘要、完成范围和未决事项。

## 6. 未知结果与重复请求

- 同一请求 ID 不能导致第二次派发；存在已完成记录则返回原结果。
- 超时或取消可能发生在派发之后，不能返回笼统“失败，可重试”。
- 结果未知时只允许观察与状态查询，冻结新的修改动作。
- 业务页面能够证明效果时，展示证据；恢复修改仍通过可信宿主的继续入口核对控制状态。
- 运行时重启或记录丢失时，不承诺跨重启的 exactly-once；旧请求不得自动迁移到新运行时重放。
- 应用内部网络提交无法由设备控制层强制回滚，取消只停止后续动作。

## 7. 错误类别

| code | 含义 | 推荐恢复 |
| --- | --- | --- |
| `DEVICE_UNAVAILABLE` | 设备断连或调试不可用 | 重连后重新观察 |
| `AUTHORIZATION_REQUIRED` | 未授权或控制权已交还 | 用户恢复控制 |
| `DEVICE_LOCKED` | 设备锁定 | 用户解锁并确认继续 |
| `SESSION_BUSY` | 另一会话持有租约 | 等待或由用户切换拥有者 |
| `STALE_OBSERVATION` | 引用/坐标上下文已过期 | 新快照 |
| `CAPABILITY_UNAVAILABLE` | 输入、截图等能力不可用 | 显示具体限制或交给用户 |
| `OUTCOME_UNKNOWN` | 已派发或可能派发但结果不明 | 观察，不重放 |
| `CANCELLED` | 请求被取消 | 同时读取 dispatch，不能假设无效果 |

## 8. 页面内容与任务边界

快照中的文字来自第三方 App，只是待处理数据。页面上出现“忽略原任务”“发送验证码”等指令不能修改任务目标、控制权或工具策略。

不把完整页面文字原样混入协议错误；日志记录状态和合成定位信息，默认不记录用户输入、令牌、订单详情或截图。

## 9. 面向用户体验的任务状态

工具响应是动作级别，聊天和通知需要任务级别的连续状态。宿主适配器应将每个请求绑定到 `taskId`，由可信控制层产生有序事件；模型不能通过生成一段文本宣称控制权已经交还。

建议事件包含：任务 ID、递增序号、发生时间、运行时身份、当前阶段、等待原因、是否需要用户处理、已确认进度和未决请求引用。UI 从统一状态派生展示，晚到事件不能覆盖更新的暂停或停止状态。

- 阶段：准备、执行、等待、核对、已结束；连接状态与控制状态独立保存。
- `phone/attention` 将同一状态投影到浮窗、通知和聊天任务卡；通道的授权、系统接收、展示确认与用户回应分别记录。
- 需要用户处理、控制失效或任务结束时，提高触达优先级并显示下一步；普通阶段变化不产生逐条打扰。
- 无法保证任何可信控制入口可达时，控制层停止接纳新的修改动作，而不是等待模型发现通道失效。
- 暂停/接管先产生请求状态，控制层确认停止接纳修改后才标记已生效。
- 等待原因区分模型、页面加载、重连和用户处理；没有事件时不制造进度。
- 人工处理可能包含敏感内容时暂停观察，保留任务摘要，继续后再获取新快照。
- 结束事件包含完成范围和未决事实，不以最后一次工具的 `ok` 直接推导任务完成。

传输方式、持久化范围和事件 schema 在实现前细化；跨进程恢复不得沿用旧租约或自动重放请求。
