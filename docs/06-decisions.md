# 设计决策与待验证项

状态：设计期记录。标记“拟定”的决策可在实测后修改，并说明原因。

## D01：独立项目，宿主集成优先

**拟定**：PalmRelay 独立维护产品设计与控制协议，首个宿主为 AndChamber。

理由：已有聊天与本地 Agent 运行基础可用于验证体验，设备控制不应与特定聊天 UI 绑定。第一版不同时承担完整独立 Agent 运行时的开发。

待决：后续实现放入本仓库的 Android 库、宿主模块或独立应用的具体组合，以及版本与发布机制。

## D02：ADB 是首个验证后端

**拟定**：先把已证明可行的路径产品化验证，消除手动命令与架构转译依赖。

待决：原生 ABI 子进程与原生协议客户端的取舍。必须结合 Android 执行限制、配对兼容性、许可证与维护能力，不预设某个库已经满足要求。

## D03：手机控制独立于浏览器生命周期

**拟定**：使用独立会话租约，打开其他 App 不自动撤销控制。

理由：跨 App 是目标行为；用户接管、锁屏、任务停止才是关键控制事件。Android 服务、通知和后台限制仍需按系统版本验证。

## D04：观察引用优先，坐标兜底

**拟定**：优先节点定位；缺失时使用绑定最新截图的坐标。

理由：纯坐标脚本对布局变化敏感，纯节点方案也无法覆盖所有界面。后端必须真实声明能看到什么、能做什么。

## D05：结果未知时不重放

**拟定**：单次派发、请求去重、未知结果进入观察模式。

理由：提交之后连接中断不代表提交失败。设备工具无法保证业务服务的事务幂等性。

范围：运行时内做可靠去重；跨重启不声称无条件 exactly-once，恢复时检查页面并由用户决定继续。

## D06：围绕完整用户旅程打磨差异化

**拟定**：将表达目标、就绪引导、控制交接、等待反馈、中断恢复和结果交付作为核心产品设计对象。

理由：技术上能操作并不意味着用户愿意反复使用。设置负担、重复确认、来回切换、无法判断进度和中断后重头开始，都可能抵消自动操作节省的时间。

验证使用独立构造的通用任务与合成界面，覆盖读取、修改和多步骤操作。用户私下给出的经历和任务只能启发问题抽象，未经明确许可不公开为案例、产品承诺或验证记录。

## D07：文档先行

**本轮已确定**：只交付设计与品牌 SVG，不创建应用、自动化代码、构建系统或安装包。

后续启动实现需要明确授权，先做 P0，并同步更新文档中的提案状态。

## D08：先做链路原型，再固定体验相关协议

**拟定**：P0 就验证首次使用、再次使用、暂停/接管和恢复流程；任务状态、等待原因和控制确认是架构要求，不是 UI 最后的装饰。

待决：最少必要的状态事件、可选悬浮入口的收益、不同设备上的恢复成本，以及面向用户的反馈时间预算。
