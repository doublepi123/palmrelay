# 产品设计

状态：提案。本文定义目标，不代表已经实现。

## 1. 一句话定位

**PalmRelay 是手机上的执行型 Agent：理解你的目标，操作已登录的 App，把可核对的结果交还给你。**

产品的核心循环是：

**表达目标 → 就绪检查 → 交接控制 → 看懂进度 → 纠偏与恢复 → 核对结果 → 交还控制。**

## 2. 首批用户与需求

首批面向愿意开启 Android 开发者选项、已经使用 Agent 工具的用户。这一阶段优先降低重复操作成本，而不是覆盖所有手机用户。

| 需求 | 用户的目标 | Agent 的交付 |
| --- | --- | --- |
| 查信息 | 不想逐条浏览资讯 | 有读取时间、覆盖范围的主题摘要 |
| 办服务 | 不想层层找入口 | 执行一次已授权操作并核对业务状态 |
| 整理比较 | 不想来回切 App 抄写 | 后续提供来源明确的对比结果 |

## 3. 先设计完整链路

产品价值以用户完成一个目标的总成本衡量，而不是支持了多少按钮或特定 App。

| 阶段 | 用户真正关心的事 | 产品责任 |
| --- | --- | --- |
| 表达目标 | 我是否必须讲得很技术化？ | 接受自然语言，复用已知上下文，只追问影响行动的歧义 |
| 准备执行 | 为什么现在不能开始？ | 自动检测就绪条件，只展示当前缺少的一步，保留原任务 |
| 交出控制 | 手机接下来会发生什么？ | 说明将切换 App、当前目标和接管入口，避免重复确认 |
| 执行等待 | 在工作、在等待，还是卡住了？ | 用阶段、原因和更新时间说明进度，不堆工具日志 |
| 临时打断 | 我需要用手机或改目标怎么办？ | 暂停/接管入口可达，保留已完成部分，解释已经发生的动作 |
| 恢复任务 | 还要从头说一遍吗？ | 重新观察后从可验证的位置继续，关键条件变化才再次确认 |
| 交付结果 | 做完了什么，还有什么没做？ | 先给结论和未完成项，再提供可展开依据；结束控制 |

首版使用独立构造的读取、编辑、页面内操作与多步骤导航任务覆盖这些阶段。测试场景是验证载体，不作为垂直业务定位，也不发布来自用户聊天的实际任务。

详见[交互设计](04-experience.md)中的首次使用、日常使用和中断恢复流程。

## 4. 首版范围

- 单用户、单手机、单个持有控制权的会话。
- 本地 Agent 宿主优先，Android 11+ 无线调试作为首个验证路径。
- 亮屏、已解锁、用户在场的交互式任务。
- 普通 App 的可见页面；可观察性不足时交还用户。
- 首次配对由用户在系统设置中完成必要操作。
- 任务入口以自然语言为主；可选通用示例帮助用户表达目标，不绑定某个第三方业务。

后续范围：更易启用的设备后端、跨 App 工作流、独立 App 形态。

定时执行、锁屏操作、远程实例控制、全天无人值守需单独设计和验证，不纳入首版承诺。

## 5. 用户如何控制执行

- 一次任务授权对应一个会话和一部手机，控制状态持续可见。
- 明确提出的修改目标可授权其必要动作；读取目标不推导为修改目标，新的目的地或关键条件变化时才追问。
- 每一步不弹出重复确认；遇到超出任务范围的操作、登录或无法确定结果时再交互。
- 用户可暂停、接管、停止任务。停止不意味着撤销已经完成的操作。
- 恢复之前重新观察手机界面，不能沿用被接管前的坐标和假设。

## 6. 产品差异化

1. **真实 App 场景**：使用用户已有登录状态，而不是要求服务都提供 API。
2. **结果可信**：展示业务状态和证据来源，而不只展示工具调用成功。
3. **手机就是执行现场**：用户能看见操作、随时接回控制。
4. **自然语言与快捷任务共存**：常用任务一键发起，复杂目标可以继续对话。
5. **宿主可集成**：保持协议边界，首个宿主为 AndChamber。
6. **少打断、能接续**：用户临时离开或介入后，不必重新描述目标、重复完成前置步骤。

## 7. 衡量方式

正式成功率在实现后测量，此处不填写假数字。

- 端到端任务完成率：有业务证据的完成次数 / 有效任务尝试次数。
- 连接恢复率：已配对、系统允许连接的中断场景中，成功恢复传输的比例。
- 结果误报次数：没有证据却声称成功，作为发布阻断项。
- 人工介入原因：首次授权、登录、界面不支持、连接失败、结果不确定等分开统计。
- 任务耗时：连接、观察、模型决策、执行、验证分别计时。
- 工具调用数与图像用量：优化不必要的重复观察，不牺牲结果验证。
- 首次价值耗时：从第一次表达目标到得到第一个有用结果，包含设置成本。
- 重复使用成本：已配对用户从表达目标到开始执行的步骤数和耗时。
- 非必要打断：重复确认、重复输入和来回切换的次数。
- 进度理解度：用户能否说清现在做到哪里、在等什么、是否需要自己处理。
- 恢复成本：一次中断后用户需要多少操作、是否必须重述目标、是否误重复已完成部分。
- 控制反馈延迟：用户发出暂停/接管意图到可见反馈、停止接纳新动作的时间分别测量。

## 8. 数据处理原则

“在本机操作”不等于“所有数据都在本机”。页面文字和截图可能进入所选模型的上下文。开始使用时应清楚说明数据路径。

优先传递任务所需的页面内容，避免无关账户信息。临时素材保存在应用私有区域，按任务生命周期清理；聊天中已发送的内容按宿主和模型服务的数据策略处理，不能承诺本地删除会同步删除远端副本。
