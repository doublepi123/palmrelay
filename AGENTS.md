# Repository instructions

## Scope

This repository is in the design phase. Do not implement an application, SDK, executable automation, build pipeline, or runtime unless the user explicitly requests implementation. SVG brand artwork and documentation are in scope.

Read README.md and the relevant design document before changing the proposal. Keep proposed behavior separate from verified capability. Do not silently turn an open decision into a shipped feature.

## Language

User-facing documentation is Simplified Chinese. Keep technical identifiers and protocol names in English. Examples must remain consistent across documents.

## Privacy

This repository is public. Never add personal account names, device identifiers, order numbers, addresses, private domains, real IP addresses, pairing codes, credentials, or private screenshots/logs to repository content or commit messages.

Use example.com, 192.0.2.1, fictional package names, and unmistakably synthetic identifiers. Loopback 127.0.0.1 is allowed in architectural examples. Never copy observed phone content into fixtures.

User conversations and exploratory tasks are inspiration, not publishable case studies. Do not publish or paraphrase those tasks as examples, product commitments, benchmarks, or validation evidence without explicit permission. Construct independent, generic scenarios instead. Prioritize the end-to-end user journey over a list of app-specific automations.

Before every commit and push, inspect the entire staged diff and outgoing commits for private information. Approved existing Git author/committer metadata is permitted; do not modify global Git identity or rewrite history without authorization.

## Maintenance

Keep local Markdown links valid. Preserve SVG viewBox values and accessibility labels. Brand artwork must not load remote resources or include scripts. When adding protocol examples, make required identities and outcome states explicit.
